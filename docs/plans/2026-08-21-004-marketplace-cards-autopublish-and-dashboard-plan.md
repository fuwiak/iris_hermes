# План: автопубликация карточек на маркетплейсы + авто-дашборд из МоегоСклада

Источник: созвон 21.08.2026 (заказчик ↔ разработчик). Статус: требования зафиксированы,
идёт прототип. Следующий синк — понедельник; промежуточные результаты показывать сразу,
не накапливая («показывай, что получается, чтобы корректировали»).

## Цель

Система заменяет человека, который вручную переносит данные из МоегоСклада и заполняет
карточки на площадках. Две основные ценности:

1. **Автоматическое создание и публикация карточек** на всех площадках + синхронизация
   между ними.
2. **Аналитика и рекомендации по продвижению** — отдельно для каждой площадки.

## 1. Дашборд

- Дашборд формируется из МоегоСклада автоматически, без ручных шагов.
- Обновляется сам (авто-рефреш данных).
- Прототип: **два маркетплейса** (Flowwow + Яндекс) как источники данных, их цифры
  участвуют в расчёте дашборда.
- Понять, достаточно ли для аналитики просто доступа в МойСклад + кабинеты площадок.

## 2. Карточки товаров (флоу создания)

1. Пользователь выбирает наименование букета **из МоегоСклада** — букеты всегда
   сначала создаются там, значит состав уже известен системе.
2. Прикрепляются фотографии.
3. Система **генерирует описание**.
4. Пользователь выбирает площадки для публикации — маркетплейсы **и сайт**.
5. Для каждого ресурса — **свой алгоритм/адаптер**: например, для Flowwow система
   должна знать требования к описанию, к картинкам и т.д.
6. Синхронизация карточек между площадками.

## 3. Аналитика продвижения и рекомендации

- Рекомендации отдельно на каждую площадку (площадки работают по-разному).
- По Flowwow: есть большой архив — анализировать **корреляцию между содержимым
  карточки и её позицией** в выдаче.
- Изучать правила продвижения/размещения площадки и на их основе давать рекомендации:
  что сделано правильно, что нет.
- Отчёт по аналитике: воспроизвести существующий отчёт, отобразить нормально
  (цифры, диаграммы), и главное — система должна **сама автоматически получать**
  этот отчёт.

## 4. Заказы через API

- Поступил заказ на площадке → автоматически записывается в МойСклад (и далее по цепочке).

## 5. Доступы

- **Яндекс**: доступ есть, должно работать штатно.
- **Flowwow**: токен получен через службу поддержки, действует **около часа**;
  ссылка на скачивание — похоже, **одноразовая**. Задача: проверить, рабочий ли токен,
  и понять, какие данные по нему реально можно вытащить. Описание карточки на Flowwow
  уже закидывалось вручную (есть образец).

## 6. Telegram (дашборд Рассылки)

- Добавить **обычную загрузку картинок с компьютера** в сообщения Telegram.
- Лимиты Telegram на рассылки — жёсткие; тема **отложена**, делается отдельной
  доработкой (не в этом прототипе).

## Проверка отчёта (созвон 22.08.2026)

Методика клиента: взять образец отчёта, вырезать 50% месяцев, восстановить их
только из данных МоегоСклада; система должна сама сказать, каких цифр ей не
хватает (маркетплейс/категория), принять их вручную («вот тебе недостающие
цифры»), построить отчёт и сойтись с образцом; расхождения — разобрать, почему
возникли. Цель: отчёт целиком из МоегоСклада, недостающее позже подтягивается
по API из кабинетов площадок.

Реализовано: `plugins/moysklad/report_backtest.py` +
CLI `plugins/moysklad/scripts/backtest_report.py`:
`--emit-template` пишет скелет reference из рассчитанного отчёта (заменить
цифры на клиентские из Excel); `--reference --months 2026-07,2026-08` сверяет
вырезанные месяцы; `--fill missing.json` подаёт недостающие цифры;
`--dump-computed` отдаёт сгенерированный отчёт для разбора. Exit-коды:
0 сошлось / 2 не хватает данных / 1 расхождения. Формулы Excel («минус 30%»,
комиссии площадок, маржа, доля, средний чек) — `dashboard_analytics.py`,
проверены на live-каталоге (3946 клиентов).

## Возможности по API двух маркетплейсов (проверено live 23.08.2026)

1. **Создание карточки в Ирис из каталога МС** — можно. МойСклад отдаёт
   каталог букетов с составом; публикация: Flowwow `products/create`,
   Яндекс `offer-mappings` (update). UI-флоу создания — следующий этап.
2. **Размещение/изменение карточек, генерация описания** — можно. Flowwow:
   create/update/hide/unhide/archive + цены + остатки + топ-18. Яндекс:
   правка карточки (название/описание/фото) через offer-mappings, ответ —
   contentRating. Описания генерирует LLM, адаптация под требования площадки
   в промпте.
3. **Рекомендации по СЕО** — частично. Яндекс: contentRating (0–100) на
   каждую карточку из API → конкретные разборы (живой пример: 68/100 из-за
   2 фото). Flowwow: позиций выдачи в открытом API нет — рекомендации только
   по качеству контента.
4. **Что куда добавить по динамике продаж** — можно. МС: продажи по каналам
   помесячно; Яндекс: реальные заказы с SKU (продажи per карточка). Flowwow:
   заказов в API нет — динамика канала только из МС.
5. **Заказы/статусы → МС** — Яндекс: заказы и статусы читаются
   (stats/orders, orders); родная интеграция МС↔Яндекс уже синхронизирует
   заказы (счётчики сходятся 64/64, 102/104) — но МС пишет цены ДО скидок.
   Flowwow: API заказов нет — только вручную или другой канал.
6. **Прочая аналитика** — уже есть: P&L по формулам Excel, сверка
   МС↔кабинет Яндекса (в Дашборде), backtest отчёта, аудит contentRating,
   когорты Флау. Дальше: маржа per карточка, ценовые рекомендации.

## Причина «цифры не бьются» (закрыто 23.08)

Две причины, обе исправлены: (1) аналитика считала только заказы со штампом
«оплачен» — маркетплейсовые заказы без per-order оплаты выпадали; теперь
считаются все неотменённые. (2) МойСклад пишет цены ДО скидок Яндекса:
сверка live показала МС +58…82% к фактическим продажам кабинета при
совпадающем числе заказов. В Дашборде теперь блок «Сверка с кабинетом
Яндекс Маркета» с обеими цифрами (покупательская и к выплате).

## Возможности API Flowwow (проверено по всем endpoint'ам live 24.08.2026)

Что МОЖНО через открытое API продавца (все операции подтверждены):
- управлять карточками: создавать, изменять, скрывать/открывать,
  архивировать/возвращать, менять топ-18 витрины;
- читать и менять цены и остатки;
- читать список магазинов и свойства категорий.

Чего НЕЛЬЗЯ (endpoint'ов не существует, проверено — 404):
- получать заказы (ни списком, ни по одному);
- создавать заказы;
- читать отзывы, статистику продаж, позиции выдачи.

Вывод для клиента: интеграция с Flowwow ОДНОСТОРОННЯЯ — мы полностью
управляем витриной (карточки/цены/остатки) из системы, но заказы через
это API не приходят и не отправляются. Поток заказов Flowwow — только
кабинет/другой канал; динамика продаж канала — из МоегоСклада.

## Дашборд ~3300 vs Excel ~2800 (разбор 24.08)

Границы периодов корректны: месяц календарный по дате создания заказа,
неделя Пн–Вс, дубли отсекаются, отменённые исключены. Расхождение — из
цен Яндекса: МС пишет цены ДО скидок (+550–660 тыс./мес к факту). В
сверке Дашборда добавлена колонка «Оборот к Excel» (месяц с Яндексом по
ценам кабинета) — она и должна сходиться с отчётом. Также добавлен блок
«Как посчитано» с методом и списком каналов (Excel может не учитывать
Яндекс Еду/Ozon — это второй источник расхождений).

## Marketplace Ranking Engine (25.08.2026)

Клиент прислал развёрнутый разбор официальных факторов ранжирования обеих
площадок (Flowwow blog «Выдача товаров: как подняться в топе»; Яндекс
справка «Качество карточки» с опубликованными весами). Реализован
`plugins/moysklad/ranking_rules.py` — свод правил (rulebook) с 13 факторами
(6 Flowwow, 7 Яндекс, включая точные веса 27,5/25,5/18/17/7,5/4,5% и
Card Quality ≥80 → до +50% показов), плюс аудитор, который сверяет каждую
карточку с проверяемыми правилами и выдаёт находки в формате «данные
карточки → правило площадки → проблема → действие → ожидаемый эффект →
приоритет» вместо общих советов.

Endpoint `GET /cards/seo-audit` (СЕО-вкладка): 8 мс на 803 карточках,
498 карточек с находками. UI — вкладка СЕО получила панель со списком
правил; клик по правилу подсвечивает все карточки/рекомендации,
построенные на нём (и обратно — клик по рекомендации подсвечивает её
правило). Список карточек — раскрывающийся (сворачивается/разворачивается
по клику), худшие сверху. Реализовано в обоих UI (desktop + dist bundle),
11 тестов в `tests/plugins/test_ranking_rules.py`.
